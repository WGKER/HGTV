## 功能与来源

- 顶部新增「排行榜」，独立展示漫剧热播榜；推荐/搜索选择短剧时，排行榜仍然只读取漫剧。
- 来源为 `https://hongguoduanju.com/rank/hot-comic-drama`。此前漫剧推荐已使用该列表，本次补充独立入口、网站名次、热度、更新时间、总页数和刷新。
- 前三名突出显示，确认卡片进入原有详情与播放流程；返回详情前的排行榜页码和卡片焦点会恢复。刷新重新读取第 1 页。
- 同时支持流式 JSON、旧版序列化 JSON 和仅有服务端渲染卡片的响应。名次使用来源字段，不按本页下标重新编号；缺失名次/热度显示暂无。
- 排名元数据不写入收藏与观看记录。加载失败保留重试入口；加载期间切换标签不会缓存新页码与旧页内容的组合。

## 2026-10-06 界面变更：去掉翻页，改为向下追加

### 改了什么

- 热播榜（`tab==2`）和首页「精选推荐 / 热门发现」向右进入的热门集合页（`collection=="hot"`）都不再渲染
  「上一页 / 下一页 / 下一批热门」和「第 X / Y 页」：`MainActivity.catalogGrid()` 直接画出 `catalog` 里的
  全部内容（`catalog` 就是历次追加出来的整份列表），两条路径由 `appendCatalog()` 统一判定。
- 列表底部一行：左边已显示进度（`moreCountText()`，榜单用 `ranking.totalPages × 20` 给「N / M 部」，
  首页热门只给「已显示 N 部」，末页都是「已显示全部 N 部」），右边「展示更多 ↓」按钮（tag `LOAD_MORE`）。
  还有下一页时按钮可聚焦，末页只留进度文字。
- 最后一行按下键落到按钮上，再按确认或下键加载下一页（`loadMore()`：页码加一后重新请求）。
- 追加成功只接住没出现过的剧集（按 id 去重），名次与热度按页合并（`mergeRanking`），
  焦点落到新增的第一张卡片；远端长列表的 `catalogPageKey` 不带页码，滚动位置因此在追加后保持不变。
- 追加失败保留已经显示的内容，页码退回待加载的那一页，并提示「加载更多失败」；按钮留在原处可直接重试。
- 首页「热门推荐」由 3 部改为固定 10 部，第 11 部起顺延到「热门发现」（`hot.drop(10).take(10)`），
  两个分区不重复；首页只缓存一页，所以只要远端还有下一页，两个分区行末都留「查看全部」。
- 本机集合页（我的收藏、观看记录、稍后看）和搜索仍然按页切换，没有改动。
- 顶部导航去掉「收藏」「最近观看」，只留品牌 + 搜索 + 排行榜 + 设置（`nav` 4 项，设置从第 5 位挪到第 3 位，
  原来的 tab 3 / tab 4 页面删除）；首页剧架改成
  「历史记录 → 我的收藏 → 热门推荐 → 热门发现」（有稍后看内容时它作为最后一栏），每栏最多十部，
  本机没有数据的行不渲染。历史记录显示进度、未看完的条目确认后直接续播；我的收藏沿用
  `favoriteLabel()` 的更新文案。
  原收藏页的「检查更新」跟着收藏集合页、原历史页的「管理记录」跟着观看记录集合页的页头。
