# 红果 TV 原生独立版

这是独立的 **Kotlin + Android 原生 View + Media3** 工程，最低 Android 8.0 / API 26。安装一个 APK，联网后可直接浏览和播放，无需部署 Node、Docker 或填写服务器地址。

- 应用名称：红果 TV 原生版
- 包名：`com.hongguotv.nativeapp`，与旧版 `com.hongguotv` 可以并存。
- 收藏和历史独立保存在本机，不自动迁移旧版数据。
- APK 不含 JNI 库，可由 Android 在 ARM32、ARM64、x86、x86_64 上运行；视频解码能力依赖设备。
- 源码分支：`codex/kotlin-standalone`。
- [下载正式签名 APK](https://github.com/N3urda/hongguoTV-updates/releases/latest)

0.2.1 修复简介与设置切换后的焦点跳转，并适配放大字号的卡片高度。可直接覆盖安装 0.2.0，保留收藏和观看记录；见 [交付与验证记录](DELIVERY.md)。

## 0.11.0 新增

- **弹幕真的看得见了**：`DanmakuView` 原来把空态设成 `GONE`，`GONE` 的视图不参与测量、宽高恒为 0，
  「有宽高才排轨道」的条件永远不成立，接口返回几千条也一条都画不出来。现在空态用 `INVISIBLE`
  （照样被测量，只是不绘制），可见性只按「这一集有没有数据」判断，两个条件不再互相等待。
- **边拉边画**：整集要按 30 秒窗口连着拉几十页、窗口之间还有 180ms 频控间隔，等全量等于前十几秒没有弹幕。
  每到一个窗口就先铺上屏（带 token 校验，切集后到达的旧窗口直接丢弃），整集拉完再换成完整的一份。
- **播放时屏幕上只剩画面与弹幕**：整宽 96dp 的「剧名 · 第几集 + 时钟」标题条改成默认收起，
  只在唤出播放界面（底部控制条 / 播放设置 / 选集 / 播放失败）时出现。
- **上方弹幕收到最上面四分之一**：`TOP` 档的可铺区域从约三分之一收到 `0.25`，离顶边的边距从 104dp 收到 20dp，
  留白全放在下面，弹幕整体往上走、不再压画面正中。
- **播放设置面板固定为屏幕下方三分之一**，装不下的行靠上下键滚出来（焦点走到哪一行就带哪一行进可视区），
  渐变背板画在外壳上、外壳负责裁剪；行号收敛成 `MENU_ROW_*` 常量，以后插行不会让选中态错位。
- **新增「字幕大小」「字幕透明度」两条滑动调节**（60%–200% / 20%–100%，步长 10%），
  播放设置面板与设置页共用同一个控件，改的是同一份本机偏好。不用 `SeekBar`（电视上它会自己抢焦点、
  和四向锁定打架），左右键由控件自己消化、长按连续调节，上下键仍交给焦点系统。
  值统一由 `DanmakuStyle` 归一（吸附 0.1 的整数倍 → 夹进上下限 → 抹掉浮点误差），
  面板读数、写盘、读回是同一个浮点值；字号变化重排轨道，透明度只改画笔 alpha。
  设置键新增 `danmakuScale` / `danmakuAlpha`，旧备份缺这两个字段时按 100% 读回。

签名与 0.9.x / 0.10.0 相同，可直接覆盖安装并保留本机记录。详见 [0.11.0 发布记录](RELEASE_0.11.0.md)。

## 弹幕同步与搜索改造（0.10.0 起）

### 1. 弹幕：接的就是原 App 播放时用的那一份数据

找到了可以直接用的接口，并且已经实测通过（`core/src/main/kotlin/com/hongguotv/core/Danmaku.kt`、
`ContentRepository.danmaku`）：

| 用途 | 请求 / 字段 |
| --- | --- |
| 一集弹幕 | `POST https://{api5-normal-*}.fqnovel.com/novel/commentapi/comment/list/{vid}/v1/` |
| 专用请求头 | `comment-source: 601`、`server-channel: 1000`、`x-ss-stub:`（空） |
| 请求体 | `comment_source=601`、`group_type=30`、`comment_type=20`、`sort=1`、`count=90`、`aid=8662`，`business_param` 里给 `book_id`（剧集 ID）、`start_offset_time`（窗口起点，毫秒）、`playlet_item_duration`（本集时长） |
| 分窗 | 一次只返回 30 秒窗口；`extra.next_query_danmaku_list_time` 是下一个窗口起点，`data.common_list_info.has_more` 表示还没到片尾，`cursor` 原样回传 |
| 一条弹幕 | 文本 `comment.common.content.text`，时间点 `comment.expand.offset_time`（毫秒），点赞 `comment.stat.digg_count` |

`vid` 就是详情页 `vid_list` 里的那个 ID，也就是播放时用的分集 ID，不需要额外解析。
六条线路（`api5-normal-sinfonlinea / c / b`、`api5-normal-lf / lq / hl`）依次失败转移，
窗口之间留 180ms 间隔避开平台频控；一集最多 40 个窗口、最多保留 3000 条。

**播放设置里的「弹幕」一行**提供三档显示方式，选中即生效并写入本机设置（换集、重开应用都保持）：

| 档位 | 表现 |
| --- | --- |
| 全屏弹幕 | 整幅画面从上到下都是弹幕轨道 |
| 上方弹幕 | 只在画面上部约三分之一内滚动 |
| 隐藏弹幕 | 整层不可见，也不发起弹幕请求 |

**平台只放出一小部分弹幕（已实测）**：接口对匿名设备返回的是「热弹幕」样本，而不是全部。
同一个 30 秒窗口里，服务端自报的弹幕数（`common_list_info.cursor` 里的 `danmaku_window_count`）
与实际下发的条数差得很远：

| 剧集 | 服务端自报（首窗口 / 全片） | 实际拿到 |
| --- | --- | --- |
| 咱家剑宗团宠小师妹第五季 第 1 集 | 6424 / 3706 | 43（整集 119） |
| 万妖图录传第十三季 第 1 集 | 10830 / 27824 | 2 |
| 聚宝仙盆之杂灵根才是真BOSS第十三季 第 1 集 | 3137 / 8430 | 0 |
| 问鼎仙途：踏碎仙凡 第 1 集 | 1036 / 1559 | 0 |

`count` 调到 500、换 `sort`、去掉 `need_danmaku_guide_type`、加 `user_is_login`、把 `x-ss-stub` 换成
body 的 MD5、六条线路挨个试——结果都一样，所以这是平台侧的匿名采样，不是参数问题。
**表现就是「有的剧一屏弹幕、有的剧一条都没有」**，播放界面的状态行会直接报出这一集取到多少条
（`弹幕 全屏弹幕 · 119 条` / `· 无` / `· 加载中`），`adb logcat -s HongguoTV` 里也有一行
`Danmaku episode=... count=...`，便于区分「这一集本来没有弹幕」和「弹幕功能没生效」。

绘制层 `app/src/main/kotlin/com/hongguotv/nativeapp/DanmakuView.kt` 在 `setDanmaku` 时一次性排好轨道
（按时间排序 + 轨道空闲时间轮转），每帧只按当前播放位置求 x，不做排序也不做测量；
播放位置与播放状态都从 Media3 播放器现取，暂停 / 跳转 / 倍速都不会和画面脱节，
暂停时动画循环停下、继续播放时由 `onIsPlayingChanged` 叫醒。顶部 104dp（标题条）以下、
底部 120dp（控制层）以上才是弹幕区域，单帧最多画 160 条。

### 2. 搜索：漫剧不再报错，结果改成向下自动加载

- **漫剧搜索报错的根因**：App 搜索接口 `GET /reading/bookapi/search/tab/v` 现在对匿名设备返回
  **HTTP 200 + 空响应体**（六条线路、多组设备参数、GET / POST、全新设备标识都一样，
  `danmu_api` 的独立签名实现同样拿不到数据）。旧代码把空 body 直接丢给 `JSONObject`，
  抛的是 `A JSONObject text must begin with '{'`，而短剧还有一条「退回官网搜索」的兜底、漫剧没有，
  于是漫剧搜索只剩一句错误提示。现在先判空、再退回官网搜索，漫剧和短剧走同一条路。
- **翻页改成向下追加**：搜索页去掉「上一页 / 下一页」，改成和热播榜、热门集合页同一套
  「往下接」机制——滚到接近底部（或焦点走到最后两行）就静默取下一页，接在列表末尾，
  视口上方的像素一个都不动，因此不会跳回顶部。底部只留一行不可聚焦的进度文字。
- **「更多结果」从片库目录补**：官网搜索不区分内容类型、也**没有分页**——`?page=2`、`page_num`、
  `offset`、`page_size`、`count` 等参数全部被忽略，一次只给前 10 条（`totalCount` 显示有 200 左右）。
  所以搜索被拆成两段：

  | 位置 | 来源 | 说明 |
  | --- | --- | --- |
  | 第 1 页 | App 搜索接口；拿不到数据时退回官网搜索 | App 接口一次 20 条、按内容类型分 tab；官网搜索最多 10 条，按相关度 |
  | 第 2 页起 | App 搜索接口的游标；接口不可用时退回片库目录（`/category/comic-drama` / `/category/real-drama`） | 目录 24 部一页、各 34 页，每次往后扫 3 页，只留下**片名含关键词**且**界面还没见过**的剧 |

  实测「修仙 · 漫剧」（匿名）：10 + 2 + 4 + 4 + 1 = **21 条**，滚到底再收；「聚宝 · 漫剧」：10 + 1 条后收手。
  目录翻完、或者连续一轮一个新条目都没有，`hasMore` 就收掉——不会让用户一直往下滚却什么都没有。
  同一部剧的不同季、目录分页本身的重复都由「已发过名单」挡掉，界面不会看到重复卡片。
- **可选登录态（2026-10-09 复测后新增）**：设置 → 片单与设备 → 「搜索登录态」，用手机扫码粘贴
  App 抓到的 `x-tt-token`（整段 Cookie 也可以）。填上后 App 搜索接口按该账号返回数据，
  搜索第 1 页起就直接用它（一次 20 条、按短剧 / 漫剧分 tab、可继续翻页），不再依赖官网搜索与片库目录。
  口令只存在本机（`native-session-v1`）、只用于搜索请求，不进备份文件、不上传；清除口令即回到匿名请求。
  **不填也能搜索**：退回官网搜索 + 片库目录补页，这是默认路径。
- **翻页改成向下追加**：搜索页去掉「上一页 / 下一页」，改成和热播榜、热门集合页同一套
  「往下接」机制——滚到接近底部（或焦点走到最后两行）就静默取下一页，接在列表末尾，
  视口上方的像素一个都不动，因此不会跳回顶部。底部只留一行不可聚焦的进度文字。
  游标缺失或过期时回到第 1 页重新搜（提示「搜索结果已过期，已回到第 1 页刷新」）。
- **搜索框不再困住焦点**：输入框是 `EditText`，方向键会被它的光标移动逻辑吃掉，焦点回到搜索框后
  上下键就出不去。现在这两下显式交回页面：上=分类开关（短剧 / 漫剧），下=搜索结果第一张卡
  （没有结果时退到顶部入口）。

## 新拟态界面改版（0.10.0）

界面换成**新拟态（Neumorphism / Soft UI）**：全站只有一块材质，层次由「凸起 / 凹陷」与柔光
（右下深投影 + 左上浅高光）表达，
不再用 1dp 描边勾卡片轮廓；圆角整体放大一档（卡片 12–14dp、胶囊 26dp、弹窗 24dp）。

设置页分组、全部弹窗（含二维码与备份恢复）、应用图标与主题色。

**桌面图标**（2026-10-07 换版）是拟物的 Apple 标志 + 果身正中的播放三角，**背景透明**：果身用
径向渐变做迎光面与背光边缘，右下补一道环境反光，投影是它自己的接触阴影。图标文件里没有底板、
没有描边、没有圆角矩形；自适应图标的 `background` 层就是 `@android:color/transparent`。
矢量与位图（含 iOS 图标、电视桌面卡片）由 `python3 tools/app-icon.py` 从一份几何生成，
没有设备时的校对图是 `preview/icon.png`（iOS 那九张必须铺底：iOS 不收透明图）。

**桌面上如果出现一圈底板，那是启动器画的**，不是图标里的东西。模拟器上的 Lawnchair 会给每个
图标垫一块纯黑底板（深色模式），三轮实测把这件事钉死：

1. `background` 层留透明 → 黑方块；
2. `background` 换成 alpha=1 的白色 → 量到 (1,1,1)，白底叠在黑底板上，说明底板在图标下面；
3. **前景也换成全透明**（图标什么都不画）→ 那块纯黑方圆仍然在（128×128、15596 个
   `sum(rgb)<40` 的像素）。换启动器即消失。

安全区（同一台设备上量）：启动器把 108dp 画布画成 192px、只露出中央 72dp（128px）的方圆遮罩，
越出去就被切。物件因此缩到 0.80——果身整个落在中央 66dp 的圆里（最远 31dp），果叶尖到 42dp，
离遮罩边缘还有 3dp（实测果叶顶边距遮罩顶边 7px）。

**整个播放界面保持原样、不套新拟态**：顶部「剧名 + 集数」标题条（整宽 96dp 渐变 + 带投影的粗体字）、
底部控制层（三段黑渐变）、进度条（4dp 轨道 + 白色已播 + 白色圆滑块）、播放设置面板的渐变底座、
选集面板压在画面上的渐变背板。播放时这些元素一直压在画面上，柔光底板会和画面抢注意力。

设计令牌、柔光实现、组件清单与必须保持的不变量见 [新拟态界面改版说明](UI_NEUMORPHISM.md)；
没有设备时的观感校对走 `python3 tools/neumorphism-preview.py`，输出在 `preview/`
（`home.png` / `sheet.png` 是界面，`palette.png` 是强调色候选对照），
十四套主题排成 7 列 × 2 行的对比图走 `python3 tools/theme-preview.py` → `preview/themes.png`。
本轮只改 UI 层源码，`tools/verify-button-system.py`（149 项规则）、`tools/theme-preview.py`
（十四套主题的对比度自检）、`:core:test`、`:app:lintDebug`、`:app:assembleDebug` 全部通过；
**实体电视上的观感、低端 GPU 帧率、十二套浅色主题在 3 米外的焦点辨识度与 4K 画布下的对比度尚未验收**
（本轮环境没有连接设备，模拟器的系统镜像下载失败；浅色主题的焦点对比度上限是已知的，

## 界面改版（0.10.0）

## 0.7.0 新增

- **首页更紧凑**：焦点预览固定为一行剧名和一行状态，完整简介留在详情。接着看、收藏有更新各显示最多 8 部，稍后看、热门各最多 10 部；超过后从行末「查看全部」进入集合。本地收藏、最近观看及首页集合每页最多 20 部，避免一次创建全部剧卡。首屏数量不改变本机记录的保存上限。
- **快捷操作保持位置**：收藏、稍后看和隐藏更新当前卡片区域，不重建整个页面；保留每行横向位置，移除当前卡后聚焦相邻卡。返回列表保留页码，并确保恢复的焦点处于可见区域。
- **本机查询不再反复解析记录**：启动在后台载入收藏、历史、设置及首页缓存，之后通过内存索引查询；记录按变更字段合并，由后台串行写入。首页缓存独立存储，兼容迁移旧版记录，生命周期变化会请求及时写入。
- **封面和请求可以取消**：图片按实际显示尺寸采样和裁切，优先处理焦点附近内容；图片等待队列最多 24 项，低内存设备使用 1 个图片线程和 4 MiB 内存缓存，其他设备为 2 个线程和 8 MiB。保留 24 MiB 封面磁盘缓存；离开页面、换集或进入后台时释放旧图片绑定并取消相应请求，翻页与搜索也会取消前一次内容请求。
- **换集复用播放器**：普通换集复用 Media3 播放器与播放视图，更新媒体源和本集监听；故障恢复、退出和后台释放仍走完整清理。播放进度与媒体状态按可见性、播放状态和事件更新，减少后台或隐藏界面的重复工作。
- **预加载靠近片尾**：按当前倍速估算剩余播放时间，在最后 30 秒内且自动连播、网络和缓冲条件允许时准备下一集；每集最多尝试 3 次，尝试间隔至少 15 秒。仍只保留一个结果和最多 1 MiB 开头数据，2 分钟失效，取消及失败走普通加载流程。
- **避免只播声音却黑屏**：过滤已知不兼容的视频格式；优先遵守默认清晰度，若只有更高清晰度可用则显示「兼容资源」。视频轨道无法播放时显示失败操作，不把音频 READY 当成视频成功。
- **续播少一层操作**：最近观看和首页续播确认后直接播放，退出回原列表；播放中「↓」直接选集，「↑ / 菜单键」打开更多操作。选集取消恢复原播放或暂停状态。

3. 首页剧架自上而下是「历史记录 / 我的收藏 / 热门推荐 / 热门发现」，每栏最多十部，本机没有记录的剧架不占位；
   历史记录、稍后看和续播条目确认即播放，其余条目确认进入详情。行末「查看全部」进集合页，
   热播榜、热门集合页和搜索结果都停在最后一行按下键可以继续向下加载。设置中可选择 480P / 720P / 1080P 上限、是否自动连播和弹幕显示方式。

搜索页：输入关键词后结果按「向下自动加载」呈现，没有上一页 / 下一页；滚到底部或焦点走到最后一行就自动接着取。
第 1 页优先用 App 搜索接口，匿名设备拿不到数据时退回官网搜索；之后每一轮再从片库目录里筛出片名含关键词的剧接在后面（见上一节）。
设置 → 片单与设备 → 「搜索登录态」可选填 App 抓到的口令，填了以后第 1 页起就直接用 App 搜索接口。
搜索框里的上下键会把焦点交回页面（上=短剧 / 漫剧开关，下=结果第一张卡）。

播放中：确认键暂停/播放；左右跳转 10 秒，长按连续跳转；向下直接打开选集，向上或菜单键打开播放设置（清晰度 / 倍速 / 画面模式 / 弹幕 / 定时），左右换选项、确认立即生效。返回键先关闭选集或收起进度条与菜单，再退出播放；从列表直接续播时回原列表，从详情开始播放时回详情。列表恢复原卡片，远端长列表还保留追加出来的内容和滚动位置。

## 构建

需要 JDK 17、Android SDK Platform 36 / Build Tools 36.0.0。Gradle 8.14.3 包装器已包含；不需要 npm、Node 或 React Native。设置 `ANDROID_HOME`，或在本目录的 `local.properties` 写入 `sdk.dir=SDK绝对路径`。

```sh
# 仓库根目录：开发包直接可安装，无需发布私钥
./kotlin-tv/gradlew -p kotlin-tv :core:test :app:lintDebug :app:assembleDebug
adb install -r kotlin-tv/app/build/outputs/apk/debug/app-debug.apk
```

正式 APK 使用独立发布密钥，**私钥和口令不在 GitHub 中**。重建发布包时，配置以下环境变量，或创建被 Git 忽略的 `kotlin-tv/keystore.properties`：

```properties
storeFile=/absolute/path/to/your-release.jks
storePassword=your-password
keyAlias=your-alias
keyPassword=your-password
```

对应环境变量：`HONGGUOTV_KEYSTORE`、`HONGGUOTV_STORE_PASSWORD`、`HONGGUOTV_KEY_ALIAS`、`HONGGUOTV_KEY_PASSWORD`。使用自己的签名重建时，不能直接覆盖安装官方发布密钥签名的 APK；卸载会清除本机记录。更新已安装的正式版应继续使用同一发布密钥。

```sh
./scripts/build-kotlin.sh
# 输出：outputs/hongguotv-kotlin-0.7.0-android8.apk
```

## 工程结构

- `core/`：纯 Kotlin 内容列表、搜索、详情、请求签名、弹幕（`Danmaku.kt` + `ContentRepository.danmaku`）、播放地址解析、MP4 索引和分段处理；可在 JVM 测试。
- `app/`：原生电视界面、遥控器焦点、本地收藏/进度、弹幕绘制层（`DanmakuView.kt`）、Media3 播放器及自定义 DataSource。
- `core/src/test/`：固定签名对照、NIST AES-CTR 向量、跨样本/非对齐分段、AVC 索引恢复及畸形输入校验。
- `tools/signing-oracle.cjs`：仅开发期生成兼容性测试样本；运行、构建 APK 不需要它。

播放器直接通过 HTTPS 分段拉取数据，经本机 Kotlin 处理后交给 Media3。没有 JS 引擎或常驻内容服务。仅在用户打开「手机输入」或「手机备份与恢复」窗口时，APK 临时监听局域网 HTTP；最长 5 分钟，窗口关闭或应用进入后台后停止。备份下载每次二维码一次，上传成功后关闭会话并等待电视确认。页面不处理平台账号凭据或媒体。媒体只在内存中处理，不下载整部剧到存储。元数据响应、封面大小、索引数量和播放缓冲均有上限。

```sh
# 可选联网检查：真实网站和内容接口，网络变化可能导致失败
./kotlin-tv/gradlew -p kotlin-tv :core:run
# 漫剧分类、搜索两页、详情与真实视频分段检查
./kotlin-tv/gradlew -p kotlin-tv :core:run --args=--comic
# 漫剧排行榜首两页及末页：来源名次、热度、分页和重复检查
./kotlin-tv/gradlew -p kotlin-tv :core:run --args=--ranking
# 弹幕接口联调：取漫剧热播榜第一部（或直接给剧集 ID）第 1 集的弹幕
./kotlin-tv/gradlew -p kotlin-tv :core:run --args="--danmaku"
./kotlin-tv/gradlew -p kotlin-tv :core:run --args="--danmaku 7675288927619533886"
# 重新生成签名对照样本才需要 Node
node kotlin-tv/tools/signing-oracle.cjs
```
